# 《凛冬降临》· 纯文字点击式末世生存游戏

按《凛冬降临》纯文字点击式游戏项目书 V3.0 开发的数据驱动 SPA。
**当前构建：M0—M5 全部完成 —— 30 天完整流程、八个结局、动效/音效/性能/移动端打磨。**

---

## 运行

```bash
npm start          # 本地 + 局域网静态服务（默认 0.0.0.0:8123）
npm test           # 引擎 + 内容完整性 + 全界面审查 + UI 冒烟测试（68 项）
```

Windows 双击 `run.cmd` 即可（自动开浏览器并打印手机访问地址）。
也可以直接部署 `index.html` + `src/` 到任意静态服务器；无构建步骤、无框架、无第三方运行时依赖。

### 在手机浏览器上玩

**方式一：同一 Wi-Fi 直连（无需联网、不经过第三方）**

1. 在电脑上启动服务：`npm start`（或双击 `run.cmd`），控制台会打印形如 `http://192.168.x.x:8123/` 的地址。
2. 手机连同一个 Wi-Fi，浏览器打开这个地址即可。
3. 首次使用需要在 Windows 防火墙放行 8123（本机已添加规则「凛冬降临 手机预览 (TCP 8123)」，仅允许**同一局域网**访问）：
   ```powershell
   New-NetFirewallRule -DisplayName "凛冬降临 手机预览 (TCP 8123)" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 8123 -RemoteAddress LocalSubnet -Profile Any
   # 不需要时删除：
   Remove-NetFirewallRule -DisplayName "凛冬降临 手机预览 (TCP 8123)"
   ```

**方式二：公网链接（手机用流量也能开，地址每次重启会变）**

```bash
# 免登录的临时隧道；需要 cloudflared.exe
cloudflared tunnel --url http://127.0.0.1:8123 --no-autoupdate
# 输出里的 https://xxxx.trycloudflare.com 就是可以直接发给别人的链接
```

**加到主屏幕**：`index.html` 引用了 `manifest.webmanifest`（`display: standalone`），手机浏览器里「添加到主屏幕」后会全屏运行，没有地址栏。

## 架构（项目书 §22）

```
index.html            SPA 外壳（无构建）
src/
  core/     store(状态容器) · router(哈希路由) · effects(唯一结算入口) · dom(极简构造器) · util(确定性随机)
  systems/  GameTime Survival Weather Inventory Explore Event Story NPC Battle Base Mind Power Fame Quest Ending Save
  data/     items locations characters dialogue events chapters quests endings battle
  ui/       components(Button/Card/Modal/BottomSheet/Progress/Tabs/Toast/Tooltip) · shell(顶栏/导航/反馈循环)
  pages/    Home Game Action Warehouse Mind Characters Quest Base Settings Event Battle Ending Milestone
tests/      engine.test.mjs(21) · ui.test.mjs(10，含最小 DOM 垫片与真实引导链路)
tools/      serve.mjs(零依赖静态服务)
```

### 三条硬约束

1. **结算只有一个入口**：任何行动、选项、升级、加工都产出 `Outcome` 对象，由 `core/effects.js` 按固定顺序落到状态上（资源 → 状态 → 数值 → 关系 → Flag → 时间 → 后续事件 → 任务 → 存档）。规则里没有一处直接改状态又绕过反馈。
2. **数据驱动**：事件、物品、地点、人物、任务、结局、敌人、配方全部是数据；新增一天剧情 = 往 `data/chapters.js` 与 `data/events.js` 加数据，不动系统代码。
3. **反馈即时**：每次点击都会产生数值浮动、Toast、日志或界面变化；不可执行的按钮给出具体原因（缺什么、差多少、第几天开放），不存在死按钮。

### 扩展方式（M2 起）

```js
// data/events.js —— 新增事件
d4_neighbor_help: {
  id: 'd4_neighbor_help', title: '……', kind: 'story', day: 4, once: true,
  text: (s) => `……${s.stats.warmth}……`,
  choices: [{ id: 'help', label: '【帮助】', resolve: () => ({ items: { canned: -1 }, npc: { laozhou: { favor: 10 } }, minutes: 30 }) }],
}
// data/chapters.js —— 挂到当天：quests: [...], weather, temp，并在 systems/Story.js 的 DAY_SCRIPTS 登记顺序
```

## 部署 / 发布

项目是纯静态站点（无构建、无依赖），因此托管方式就是"把文件放上去"。

### GitHub Pages（推荐：手机随时能玩，地址固定）

1. 在 GitHub 上新建一个**空仓库**（不要勾选 README / .gitignore）。
2. 本地推上去：
   ```bash
   cd winterfall
   git init -b main
   git add .
   git commit -m "《凛冬降临》V3.0 · 30 天完整流程 + 68 项测试"
   git remote add origin https://github.com/<你的用户名>/<仓库名>.git
   git push -u origin main
   ```
3. 仓库 **Settings → Pages → Build and deployment → Source** 选 **GitHub Actions**。
   仓库里已经带了 `.github/workflows/pages.yml`，推送后自动发布，地址形如
   `https://<你的用户名>.github.io/<仓库名>/`。
4. 手机浏览器打开这个地址即可，也可以「添加到主屏幕」全屏运行。

`test.yml` 会在每次推送时跑全量测试（引擎 + 内容完整性 + 全界面内容审查 + UI 冒烟）。

## M5 打磨

**动效**：页面切换淡入上移、卡片入场错峰（只对首屏前 5 张生效，长列表不做一次性动画）、按钮缩放反馈、数值浮动、底部 Sheet 与居中 Modal 各自合适的入场曲线。设置页提供「完整动效」开关，写入 `<html data-motion>`；系统级 `prefers-reduced-motion` 也会自动生效（两条规则叠加，CSS 里只有一处定义）。

**音效**：不引入任何音频素材——`src/core/audio.js` 用 WebAudio 现场合成 6 种极短提示音（点击 45ms / 选择 / 奖励 / 危险 / 光脑 / 结局），默认音量 0.02—0.06。AudioContext 在第一次真正播放时才创建（符合浏览器的手势要求）；没有 AudioContext 的环境安全返回 `false` 而不抛异常（有测试锁定）。设置页提供「界面音效」开关。

**性能**（实测数字，非声明）：

| 指标 | 数值 |
|---|---|
| 手机首屏必须加载 | **22 个文件 / 传输 34 KB**（brotli） |
| 改造前首屏 | 57 个文件 / 传输 169 KB（且 `no-store`，每次打开都要重下） |
| 引擎与其余页面 | 首屏之后空闲时后台预热，切页与开局零等待 |
| 重复打开 | ETag 协商命中 304，**传输 0 字节** |
| 30 天全流程引擎模拟（273 次操作） | 25.9 ms（每次操作 0.09 ms） |
| 主界面 / 仓库 / 行动页单次渲染 | 0.19 / 0.08 / 0.21 ms |
| 任务页单次渲染（70 条任务，分页后） | 0.93 ms |

手机加载速度做了三件事：
1. **brotli 压缩**（`tools/serve.mjs`）：整站 461 KB → 151 KB，剧情数据 events.js 单文件 167 KB → 46.5 KB。
2. **缓存协商**：不再 `no-store`，改成 ETag + `no-cache` —— 没改代码就是 304 空响应，改了立刻生效。
3. **按需加载**：页面模块与游戏引擎都用动态 import。首页只需要外壳 + 首页 + 存档摘要，剧情数据与 17 个系统在首屏渲染完成后空闲时预热；点「开始游戏」时通常已就绪。首次进入未加载的页面会先显示「载入中…」占位，避免手机白屏。

长列表用 `content-visibility: auto` + `contain-intrinsic-size` 让屏幕外卡片跳过布局与绘制；数值反馈与页面重绘解耦（Toast/Pulse 走独立反馈循环，不触发页面重建，因此不会打断输入焦点或滚动位置）。测试里有一条渲染泄漏检查：反复切换页面 30 次后 DOM 节点数不得持续增长。

**移动端**：安全区四边（含横屏左右刘海）、`touch-action: manipulation` 消除双击缩放延迟、按钮与可点击卡片禁止误选中（正文仍可选中）、长文本 `overflow-wrap: anywhere` 不溢出、横屏矮屏收紧顶栏、320px 窄屏按钮组收窄间距。键盘可见焦点样式与弹层 Esc 关闭、打开弹层时焦点自动落到第一个可操作元素。

**健壮性**：未捕获的运行时错误与未处理的 Promise 拒绝都会变成一条可见反馈（同时留在控制台），不再静默失败。

**验证边界**：以上性能与结构由 Node 下的 DOM 垫片测量与测试覆盖；真实浏览器里的视觉呈现（配色观感、动画手感、音效听感、真机触控手感）需要在浏览器中人工确认——本次未能取得浏览器会话，故这两项（§25 第 7、8 条）尚未视觉验收。
